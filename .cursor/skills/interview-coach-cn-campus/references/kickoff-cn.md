# kickoff — 中国校招版

一次问一项，等回答后再问下一项。

## 岗位预设

若存在默认预设 `plc-electrical`，先读 `references/presets/plc-electrical-engineer.md`，目标岗位默认填「PLC 电气工程师」，并在 Step 通用问题后追加该预设 §10 的问题。

## 必收信息

1. **赛道**：秋招 / 春招 / 实习 / 提前批 / 社招（0–3 年）
2. **目标岗位**（可多个）与城市偏好——有 `plc-electrical` 时默认 PLC/电气相关，仍确认是否兼投相近岗（自动化、机电、运维）
3. **目标行业 / 雇主类型**：设备厂 / 集成商 / 工厂电气 / 外企工控 / 国企制造 / 其他
4. **时间线**：最近一场面试日期；距离笔试/面试还有多久
5. **最大顾虑**（一句话）
6. **面试经历**：还没面过 / 笔试过不了 / 一面挂 / 终面挂 / 有过 offer
7. **反馈直率度** 1–5（默认 4）

## 强烈建议

- 简历全文或要点  
- 2–3 家目标公司  
- 已有实习/项目/竞赛线索（后面进故事库）

## 校招专属检测

在简历分析后额外判断并写入状态：

| 信号 | 对教练的含义 |
|------|----------------|
| 只有课程项目、无实习 | 优先挖竞赛、课设、学生工作中的「个人贡献」 |
| 跨专业投递 | 需要「桥接故事」+ 专业面补基础话术 |
| 海投无回应 | 可能是简历/投递策略问题，先 `resume` / 对齐 JD，别只猛 mock |
| 目标国企/银行 | mock 加重综合岗、价值观、稳定性；少用创业叙事 |
| 目标互联网研发 | 可保留技术表达 mock，但声明不评测代码正确性 |

## 时间模式

- **≤48 小时**：急救——`prep` → 过一遍高频故事 → `hype` 式临场清单；不新建庞大故事库  
- **1–2 周**：`stories` 补缺口 + 1–2 次 `mock`  
- **3 周以上**：完整故事库 + 分形式 mock + 真题复盘闭环
