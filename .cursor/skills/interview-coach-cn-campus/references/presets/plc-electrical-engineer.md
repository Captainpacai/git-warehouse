# 岗位预设：PLC 电气工程师

**Preset ID**: `plc-electrical`  
**适用**: 校招/实习/0–3 年 · 电气自动化、机电、工控相关投递  
**默认行业画像**: 智能制造 / 设备厂 / 系统集成 / 工厂运维（可叠国企产线或外企工控渠道）

本预设被加载后：`kickoff` / `mock` / `prep` / `stories` / `salary` 均按下列口径执行；与通用 `*-cn.md` 冲突时，**以本预设为准**。

---

## 1. 岗位一句话

做的是「把工艺动作变成可靠电气与控制」：读图与柜内电气、PLC/HMI 程序、现场接线与调试、联锁与安全、故障排查；不是纯写业务代码，也不是只画建筑电气。

## 2. 雇主类型（prep / research 时先归类）

| 类型 | 面试常偏重 | 教练提示 |
|------|------------|----------|
| 设备制造商（非标/包装/锂电/光伏设备等） | 项目周期、图纸、调试出差、客户现场 | 强调抗压、出差意愿、一次把问题说清 |
| 系统集成商 / 自动化工程商 | 多品牌 PLC、方案表达、沟通甲方 | 强调学习速度、文档、跨专业协作 |
| 甲方工厂电气/设备保全 | 运维、点检、停机抢修、安全规程 | 强调责任心、安全、倒班/待命 |
| 外企工控及代理生态 | 规范、英语图纸/手册、品牌产品线 | 确认是否需要英文；少吹「从零发明」 |
| 国企/央企制造基地 | 稳定性、规矩、综合素质 | HR 与综合面权重升高 |

不确定公司类型时：先问候选人「设备厂 / 集成 / 进厂方运维 / 不清楚」，再选上表。

## 3. 典型流程（低置信默认，需候选人核实）

网申 →（笔试/测评，部分有）→ **专业面**（核心）→ **HR 面** →（有的还有）总工/部门负责人终面。  
群面相对互联网少见，但大型集团校招仍可能出现——以候选人情报为准。

## 4. 专业面题库方向（练表达结构，不冒充标准答案）

出题与追问围绕下面模块；**每次 mock 选 4–6 个点**，不要一场塞完。

### A. 电气基础

- 主回路 / 控制回路、接触器继电器、断路器选型思路（按什么选，不是背型号表）
- 看图：一次图、二次图、接线图里你怎么找信号  
- 接地、短路保护、急停与安全回路（至少能讲清「为什么不能随便短接」）

### B. PLC 与程序思维

- 扫描周期、输入映像、输出刷新（用自己的话讲清）  
- 常用逻辑：启停、互锁、联锁、故障复位、自动/手动  
- 定时器/计数器、状态机或步进（能拿一个真实小程序讲）  
- 品牌可按候选人经历：西门子 / 三菱 / 汇川 / 欧姆龙等——**以简历出现的为准**，勿强行考没写过的品牌细节  

### C. 现场与调试

- 上电检查顺序、点对点、空载/负载调试  
- 典型故障：模块无通信、动作偶发、传感器误触发——你怎么缩小范围  
- 与机械/工艺/客户的扯皮：信号定义、时序、谁改图  

### D. 传动与现场总线（按简历深度）

- 变频器/伺服：启停、加减速、故障码思路  
- 通信：Modbus / Profinet / EtherCAT 等——「用过什么、解决过什么」，禁止编造协议细节  

### E. 安全与职业素养

- 锁死挂牌、带电作业边界、个人防护  
- 出差驻场、加班调试、文档与版本管理（程序备份、改点记录）

**教练边界（每场专业面开头声明一次）**  
「我主要评你的**表达是否清楚、排查是否有章法、安全意识是否在线**；具体型号参数、标准条款、程序能否上线，需要你对照手册/真机/老师傅验证。」

## 5. HR / 综合面高频（本岗位特化）

| 考察点 | 候选人应准备的方向 |
|--------|-------------------|
| 为什么做电气/自动化 | 兴趣要落到「现场/设备/动手」而非空泛「国家需要」 |
| 能否接受出差/驻场/加班 | 如实 + 边界；设备岗常回避不了，装永远 996 也假 |
| 能否下现场、不怕脏累 | 用实习/实训具体场景证明 |
| 职业规划 3–5 年 | 调试 → 能独立负责工位/产线模块 →（可选）方案或带小组；勿一开口就「转管理/考公」除非属实 |
| 薪资期望 | 见本预设 §8；结合城市与雇主类型 |

## 6. Mock 默认配方

| 命令 | 建议构成 |
|------|----------|
| `mock 专业面` | 1 个项目深挖 + 2 个基础/逻辑题 + 1 个故障排查口述 + 1 个安全/现场情境 |
| `mock HR面` | 动机、出差驻场、抗压、团队冲突、期望薪资铺垫 |
| `mock 技术表达` | 让候选人用 8–10 分钟讲「某一个工位/设备」控制思路 + 追问联锁与故障 |
| `mock 终面` | 匹配度、学习能力、长期留下意愿；少刷偏难怪题 |

难度：故事库 <3 个时，专业面以「讲清一个实训/课设」为主；≥5 个后再加压故障与联锁追问。

## 7. 故事库标签（本岗位必备清单）

至少覆盖下面标签中的 **5 个**（可一文多标）：

1. `项目交付` — 课设/实训/实习中做出过可演示动作  
2. `故障排查` — 遇见过异常并定位（哪怕很小学）  
3. `改图改程序` — 需求变更、现场改点  
4. `协作` — 和机械/同学/师傅/甲方对齐信号  
5. `安全或规范` — 一次按规程避免风险，或吸取教训  
6. `抗压` — 截止调试、通宵、客户催  
7. `学习迁移` — 换品牌/换设备时怎么上手  

弱故事特征（要打回重写）：只有「我们小组做了生产线」——必须能答出：**你负责哪几个 I/O 或哪段逻辑、关键怎么定义、出过什么错**。

## 8. 谈薪口径（指导研究，不编数字）

- 对比维度：同城、同届、**电气/自动化**、设备厂 vs 进厂方（结构差往往很大）  
- 总包常谈：月薪、几次薪、试用期比例、驻外补贴、项目奖金、五险一金基数  
- 设备/集成岗：问清**出差补贴、驻场补助、周末调试是否调休**——有时比多 200 底薪更实在  
- 国企厂方：档位可能更僵，谈点转向补贴、宿舍、户口/档案、培养路径  
- 话术仍用 `salary-negotiate-cn.md`；区间必须来自候选人自己的调研  

## 9. 简历 / 定位（`resume` / `pitch` 时）

优先写清：

- 用过的 **PLC 品牌与软件**、是否独立写过程序  
- **现场调试**天数/是否跟过安装接线  
- 一张能讲的图：系统框图或安全回路/主控思路（面试口述即可）  
- 量化：点数规模、工位数、故障恢复时间、自己负责的模块  

避免：堆砌无关单片机竞赛却写不出一个联锁；把小组成果写成个人全能。

3. 能否接受出差驻场？可接受的大概频率？
